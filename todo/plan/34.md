# Implementation Plan: Story and Comment Creation (Task 34)

## Overview
Implement CRUD operations for creating stories and comments. Transition the `Item` schema from using numeric `id` for relationships to using MongoDB `ObjectId` as the primary reference. 

## The "Legacy Data" Challenge
The current dataset uses numeric HN IDs. To maintain consistency, we will perform a one-time migration to map existing `id` (Number) to `_id` (ObjectId) and update all `kids`/`parent` relationships to reflect these new `ObjectId` references.

## Architecture Decisions
- **Identity:** Use `ObjectId` as the primary key (`_id`) for all items.
- **Relationships:** `kids` and `parent` will store `ObjectId` references.
- **Legacy Support:** Keep `id` (Number) as a secondary field for reference/lookup purposes, but treat it as a legacy ID.
- **Atomicity:** Use `$push` (for `kids`) and `$inc` (for `descendants`) to ensure atomic hierarchical updates.

## Task List

- [ ] **Task 1: Update `Item` Schema:** Add `ObjectId` relationships. Ensure `id` (Number) is kept for legacy compatibility but is no longer the primary key.

| Risk | Impact | Mitigation |
|------|--------|------------|
