### Observed
* `storiesController.voteStory` returns a hardcoded mock response and score delta; no database persistence or validation checks exist.
* The `User` schema has no fields for managing vote histories.

### Acceptance Criteria
* Data Model Schema:
  * Establish a `Votes` collection (or an equivalent nested structure) mapping a user's ID to their active vote direction (`1` for upvote, `-1` for downvote) on specific item IDs.
  * *Note: Removed feature: Karma. Do not implement.*
* Idempotency and Toggle Logic:
  * New Vote: Apply the vote direction (+1 or -1) to `Item.score` and save the vote record.
  * Duplicate Vote: If a user submits the same vote direction on the same item, treat the action as an "undo" toggle: remove the vote record and revert `Item.score` back to its neutral state.
  * Vote Switch: If a user changes their vote (e.g., from +1 to -1), update `Item.score` by `-2` and update the vote record.
* Controller Response:
  * Return the updated `score` and the user's active vote state: `{ score: number, userVote: 1 | -1 | 0 }`.
