### Observed
* `be/src/controller/storiesController.js` contains placeholder implementations for `createStory` and `createComment` that return sample JSON but do not persist data to the database.
* `be/src/services/storiesService.js` implements `getStories` and `getItemWithComments` but lacks creation or write helper methods.
* `be/src/models/itemModel.js` defines fields used by the service (`id`, `kids`, `parent`, `descendants`) but has no schema constraints or hierarchy update mechanics.

### Acceptance Criteria
* Service Methods:
  * Implement `storiesService.createStory(data)` and `storiesService.createComment(data)`.
  * Use the database's native string/ObjectId (`_id`) as the primary key rather than maintaining a custom sequential numeric ID.
* Hierarchy and Recalculation:
  * When a new comment is created, append its ID to its immediate parent's `kids` array using an atomic `$push` operation.
  * Update the total comment count (`descendants`) **only** on the root Story document. Locate the root story via an explicit `storyId` parameter in the payload and increment its `descendants` count by `1` using `$inc`.
* Controller Response:
  * Controllers must return an HTTP `201 Created` status with the fully saved, leaned, and serialized item document upon success.
  * On schema validation failures, return an HTTP `400 Bad Request` with structured error feedback specifying the invalid fields.
