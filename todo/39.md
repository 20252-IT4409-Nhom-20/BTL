### Observed
* Validation is handled with ad-hoc manual checks in various controller methods.
* `be/src/app.js` lacks HTTP header security, explicit request payload limit controls, cross-origin resource sharing limits, or API rate limiting.

### Acceptance Criteria
* Shared Schema Validation:
  * Define explicit validation schemas (using library like Zod or Joi) for user registration, authentication, stories, comments, and votes.
  * Implement route-level validation middleware. If validation fails, intercept the request and return an HTTP `400 Bad Request` with a structured list of field-level error messages.
* Request Hardening Middleware:
  * Mount security middleware inside `be/src/app.js`: `helmet` for HTTP header security, `cors` configured with strict origin restrictions, and specific body-parsing size limits (e.g., maximum 10kb for JSON payloads).
  * Configure API rate-limiting limits (e.g., `express-rate-limit`) applied globally, with tighter throttling thresholds on authentication and content creation paths.
  * *Note: Rely on Mongoose's built-in schema casting to mitigate NoSQL injection risks rather than writing custom query-stripping middleware.*
