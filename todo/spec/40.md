# Spec: Backend Logging and Error Handling (Task 40)

## Objective
Establish a robust, standardized logging and error handling framework to improve maintainability and debuggability. This replaces ad-hoc console logs and try-catch blocks with centralized middleware.

## Tech Stack
- Framework: Express.js
- Logger: Pino, pino-http
- Error Handling: Custom `APIError` class

## Commands
- Build: `npm run build`
- Test: `npm test`
- Lint: `npm run lint`

## Project Structure
- `be/src/utils/logger.js`: Centralized logger configuration.
- `be/src/middleware/errorHandler.js`: Global error handling logic.
- `be/src/app.js`: Middleware registration.

## Code Style
- Use `logger.info()`/`logger.error()` instead of `console.log()`/`console.error()`.
- Use structured JSON logs in production, pretty-print in development.
- Throw instances of `APIError` in controllers to be caught by the global error handler.

## Testing Strategy
- Unit tests for `APIError` serialization.
- Integration tests to verify `errorHandler.js` returns correct JSON structure for different error types.
- Integration tests to verify `pino-http` logs requests.

## Boundaries
- Always: Log errors with `logger.error()`, separate dev/prod logging config.
- Ask first: Changing the error response schema.
- Never: Expose stack traces in production responses.

## Success Criteria
- [ ] `pino` and `pino-http` installed and configured.
- [ ] Unified `APIError` class implemented.
- [ ] Global `errorHandler` middleware catches errors and returns `{ status: "error", code: string, message: string }`.
- [ ] No inline `try-catch` blocks returning responses; all errors routed to `next(err)`.
- [ ] Stack traces hidden in production.
