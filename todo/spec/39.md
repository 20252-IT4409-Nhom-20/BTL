# Spec: Backend Schema Validation and Hardening (Task 39)

## Objective
Centralize input validation to prevent invalid data and enhance security through request hardening middleware.

## Tech Stack
- Framework: Express.js
- Validation: Zod
- Security: Helmet, cors, express-rate-limit

## Commands
- Build: `npm run build`
- Test: `npm test`
- Lint: `npm run lint`

## Project Structure
- `be/src/validation/`: Directory for validation schemas (e.g., `storySchema.js`, `userSchema.js`).
- `be/src/middleware/validate.js`: Generic middleware to run Zod schemas.

## Code Style
- Define Zod schemas for all request payloads.
- Use reusable validation middleware in route definitions.

## Testing Strategy
- Unit tests for validation schemas.
- Integration tests for routes: ensure invalid inputs return 400 Bad Request with field-level errors.

## Boundaries
- Always: Validate all request inputs (body, params, query).
- Ask first: Modifying global security headers or rate limiting thresholds.
- Never: Implement custom NoSQL injection sanitizers; rely on Mongoose schema casting.

## Success Criteria
- [ ] Zod schemas defined for auth, stories, comments, votes.
- [ ] `validate` middleware implemented and applied to routes.
- [ ] 400 Bad Request returned with field-level error messages on invalid input.
- [ ] `helmet` configured for header security.
- [ ] `cors` restricted to allowed origins.
- [ ] Rate limiting enabled for auth and creation endpoints.

## Open Questions
- Need to determine specific rate limiting thresholds (e.g., requests per minute).
