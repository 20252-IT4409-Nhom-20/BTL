### Observed
* No standardized timestamps, log levels (info, warn, error), or request metadata, making production debugging and log filtering difficult.
* No unified middleware logging incoming HTTP requests, response statuses, or response times.

### Acceptance Criteria
* Structured Logger Setup:
  * Install `pino` and `pino-http` as production dependencies.
  * Create a centralized logger in `be/src/utils/logger.js` that outputs structured JSON in production, but uses human-readable formatting (like `pino-pretty`) in development.
  * Register the `pino-http` middleware in `be/src/app.js` to automatically log the method, path, status, and latency of all incoming requests.
* Unified API Error Structure:
  * Implement an `APIError` class extending the native `Error` constructor to capture HTTP status codes and machine-readable error codes (e.g., `UNAUTHORIZED`, `NOT_FOUND`).
  * Refactor controllers to pass runtime errors to the next middleware via `next(err)` instead of inline try-catch response blocks.
* Global Error Middleware (`middleware/errorHandler.js`):
  * Intercept all errors and format outbound payloads into a consistent JSON envelope: `{ status: "error", code: string, message: string }`.
  * Use `logger.error(err)` to record internal 500 errors to the server console.
  * Ensure raw error stacks are excluded from client responses in production (`NODE_ENV === 'production'`).
