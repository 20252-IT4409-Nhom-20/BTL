* `storiesController.deleteStory` returns a placeholder deleted response; there is no edit endpoint for comments or stories.
* The `Item` model has `deleted`, `by`, and `parent` fields suitable for soft-delete and ownership checks; the `User` model stores user roles.
* Access control and authorization checks are currently bypassed or unimplemented in the routing layer.

### Acceptance Criteria
* Service Layer CRUD:
  * Implement `storiesService.deleteItem(itemId, actor)` and `storiesService.editItem(itemId, updates, actor)`.
* Access Control Matrix:
  * Allow only the original author (`Item.by`) or an administrator (where `User.role === 'admin'`) to edit or delete an item.
  * Return `403 Forbidden` if an unauthorized user attempts to perform these actions.
* Edit and Soft-Delete Behavior:
  * Soft-Delete: Instead of purging documents, set `deleted: true`. Automatically replace public content fields (`text`, `by`) with the string `[deleted]` in response serializers, preserving nested child comments and hierarchy pointers so subtree rendering does not break.
  * Edits: Restrict edits to a 2-hour window from the creation timestamp (`time`). Attempts outside this window must return a `400 Bad Request` indicating the editing period has expired.
  * Record edit tracking metadata (`editedBy`, `editedAt`) directly on the updated item document.
